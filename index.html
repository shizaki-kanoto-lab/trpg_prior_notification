TRPG 卓の Discord Bot ／ 仕様書

卓通知Bot 仕様書

GM が回す TRPG 卓について、CS 提出の管理、セッション前のお知らせ、セッションルーム（ココフォリアなど）の URL の共有、Notion の記録の更新を自動で行う Discord Bot の仕様です。セットアップの手順は README を見てください。

動く場所
Cloudflare Workers（無料プラン）
データの置き場
Notion（卓予定・卓参加者・セッション日程・やることリスト・卓報告）
日程の照合先
Google カレンダー（iCal の非公開 URL で読み取り専用。使わなくてもよい）
時刻
すべて設定のタイムゾーン（既定は日本時間）の現地時刻で扱う
使う人
GM 1人につき Bot を1つ動かす。コマンドとボタンを使えるのは GM（GM_USER_ID）だけ
動き方
Discord のスラッシュコマンド /卓、10分おきの定期確認、毎朝9時の確認、セットアップ画面（/setup）

対象になる卓

  • コマンドの「卓」欄の候補：卓予定の「PL/GM」が KP・GM・DL・SKP のどれかで、状況が「完了」「流卓」以外の卓。
  • 定期確認の通知：上のうち、告知先が入っていて（/卓 連携 か /卓 チャンネル 済み）、状況が日程決定前でない卓。
  • 照合・流卓予定日の知らせ：状況が「完了」「流卓」以外のすべての卓（PL として参加する卓も含む）。
  • 日程決定前の状況（既定）：そのうち・メンバー募集中・GM宛なし・仮約束・メンバー調整中・日程打診様子見・日程調整待ち・日程調整入力待ち。

3. スラッシュコマンド /卓

  • 使えるのは GM（GM_USER_ID）だけ。ほかの人が打つと「このコマンドはGM専用です」と返す。
  • 返事は打った人にだけ見える。返事の中のメンションは通知を飛ばさない。

「卓」欄の候補

  • Bot が入っているすべてのサーバーの卓を出す（どのサーバーで打っても同じ）。
  • /卓 連携 と /卓 チャンネル：卓予定の「場所」が、Bot の入っているサーバーのどれかの名前と一致する卓（まだつないでいない卓も出る）。今いるサーバーの卓が先、ほかのサーバーの卓には［サーバー名］、「場所」が空の卓は「（場所未入力）」を付けて後ろに出す。
  • ほかのコマンド：告知先が入っている卓。
  • 候補から選ばずに送っても、TAKU-12 のような卓ID か、1つに決まるシナリオ名なら卓を探す。
  • 候補を3秒以内に出すため、卓の一覧を1分、Bot のサーバー一覧を10分だけ覚えておく。

3.1 連携（/卓 連携）

  1. cs提出（はい／いいえ）：いいえ にすると、CS の提出が要らない卓として扱う。
    • CS の検出・催促・期限超過の知らせをせず、状況を「セッション開始待ち」にする。
    • 参加者を「提出済み」にする（連携で足す人も、すでにいる人も）。
    • 準備タスクは、セッションルームの URL が登録されたら完了にする。
    • /卓 状況 は「CS提出: なし」、/卓 案内 は ▼CS提出日 の段落を省く。
    • 省略したら前回のまま（初めての卓は「要る」）。いいえ から はい に戻すと「CS待ち」に戻す（提出済みのチェックは外さない）。
  2. 参加者の登録（卓参加者 DB に1人1行。すでにいる人は重ねない）
    • 参加者欄に たろう @Taro のように名前と @ を組で書くと、その名前で登録する（= : 区切りも可）。
    • @ だけなら、卓予定の PL 欄のどの名前に当たるかを探し、当たらなければ Discord の表示名で登録する。
    • 参加者欄が空なら、PL 欄の名前から探す（GM 本人と「未定」「募集」を含む書き込みは除く）。
      1. 以前「卓参加者」に登録したことがある名前なら、その Discord アカウント
      2. 卓の「場所」のサーバーで、ニックネーム・表示名・ユーザー名が合うメンバー（完全一致を優先、なければ名前を含む人。ひらがな／カタカナ、全角／半角、絵文字・記号の違いは無視。2文字未満は部分一致させない）
      3. 1人に決まらなければ、候補と一緒に「決められなかった人」として返す
    • 結果に たろう ＝ @Taro の形で、誰を誰として登録したかを表示する。
  3. 告知先・管理先：告知先を省くと、/卓 チャンネル でつないだチャンネル（同じサーバーのとき）、それも無ければ打ったチャンネル。Bot が見られなければ直し方を出す。
  4. セッション日程の取り込み：「セッション日程」にこの卓の行が1件も無ければ、カレンダーの今後の予定から一度だけ取り込む（名前は「シナリオ名 1日目」など。1回だけならシナリオ名）。前の回の翌日の回には最初から「通知しない」を付ける（連日の卓で、翌日の回の前日のお知らせが前の回より先に届くのを防ぐ）。以後は /卓 日程 のとき以外、Bot は書き換えない。
  5. CS期日：初回のセッションからの日数（候補：当日・前日・2日前・3日前・1週間前。N日前 N週間前 も可）か、20261020、20261020 2100、10/20 21:00、10月20日 21時 などの日付で指定し、卓予定の「CS期日」に実際の日付で書く。日数のときは時刻なし（その日の終わりが期限）。初回が無い卓では日数は使えない。年を省いて1か月以上前になる日付は来年とみなす。CS 提出が無い卓では使わない。
  6. 状況：「CS待ち」「セッション開始待ち」「セッション中」以外なら「CS待ち」にする。cs期日を指定したときは（「セッション中」以外なら）「CS待ち」に戻す。
  7. 準備タスク：やることリストに同じシナリオのタスクが（完了済みも含めて）1件も無ければ、「シナリオ名準備」を足す。カテゴリ TRPG、ステータス 未着手、期日は初回の1週間前、卓へのリレーション付き。
  8. 注意の表示：場所と打ったサーバーの違い、Bot が場所のサーバーにいない、場所が未入力、Bot がチャンネルを見られない、CS期日が無い、日程が無い、初回に時刻が無い。

3.2 セッションルーム（/卓 部屋登録 の返事）

  • 前日のお知らせがまだ：「前日のお知らせ（日時）に付けて送ります」
  • 前日のお知らせのあと：「開始前のお知らせ（日時、メンションなし）に付けて送ります」（その時刻を過ぎていれば「10分以内に…」）
  • もう送ってある：「参加者にはもう URL を送ってあるので、自動では送りません」
  • 初回に時刻が無い：「自動では送りません」
  • どれも「今すぐ送るときは /卓 部屋送信 を使ってください」を添える。

3.3 日程（/卓 日程）

  • 「回」の候補は、選んだ卓の全回（中止・通知なしの印つき）と、いちばん上の「＋ 新しい回を追加」。
  • 操作：中止にする／中止をやめる／通知しない／通知する。
  • 日時：入れるとその回をリスケする（終了は決まりどおり入れ直す）。
  • 回の追加：「＋ 新しい回を追加」と「日時」で、「シナリオ名 N日目」の回を作る。終了は決まりどおり。前の回の翌日なら「通知しない」を付ける（操作で 通知する／通知しない を選べばそれに従う）。行が無く卓予定の「セッション日時」で動いている卓は、その回も1日目として行にしてから足す。
  • 状況が「セッション中」でも使える。変えた内容は次の定期確認（10分以内）から通知に反映する。

3.4 終了（/卓 終了）

  1. 状況を「完了」にする（以後、通知・照合の対象外）。セッションルームの URL を送った記録を消す。
  2. 卓報告に1行作る：
    • シナリオ、日付（初日＝セッション日程のいちばん早い回。無ければ卓予定のセッション日時）
    • GM、PL（卓参加者の名前を「、」でつなぐ）
    • システム（書き換え表と選択肢で直す。9. の REPORT_SYSTEM_*）、PL/GM、卓予定へのリレーション
    • URL（卓報告に URL の列があるとき）：url 欄の値 → 卓予定の「URL」 → 同じシナリオの前の卓報告の URL の順
  3. 卓報告を作ったら、その卓の「セッション日程」の行（中止の回も含む）を Notion のゴミ箱に移す（Notion から元に戻せる）。卓報告を使っていないときは消さない。
  4. 何日かに分けた卓は、最終日が終わってから実行する。

4. 定期確認（10分おき）

告知先が入っている卓（日程決定前の卓は除く）ごとに、上から順に行う。1つの卓でエラーが出ても、ほかの卓は続ける。

4.1 CS（状況が「CS待ち」で、CS 提出が要る卓だけ）

  1. 提出の検出：告知先チャンネルと秘匿の送り先の直近50件のメッセージから、参加者が貼った CS の URL を探す。
    • 受け付けるサイト：いあきゃら（iachara.com）、Charaeno（charaeno.com）、キャラクター保管所（charasheet.vampire-blood.net）、キャラクターシート倉庫（character-sheets.appspot.com）、ゆとシートⅡ（yutorize.work、yutorize.2-d.jp）、キャラッシュ（charash.jp、charasheet.jp）、vinsanet（vinsanet.com）、Google スプレッドシート（docs.google.com）。設定で足せる。
    • 見つけたら、卓参加者に提出済み・CS URL・提出日時・メッセージへのリンクを書き、メッセージに 📥（受け取りました）を付ける。📥 は受け付けた印で、中身を確かめた意味ではない。
    • 再提出（前の提出より新しいメッセージ）なら上書きする。📥 か以前の ✅ が付いたメッセージは読み飛ばす。
    • テキストで貼られた CS は検出しない（/卓 提出 か Notion で手動）。
  2. 全員提出：参加者が1人以上いて全員提出済みなら、状況を「セッション開始待ち」にし、GM に知らせる（セッションルームの URL が未登録ならあわせて知らせる）。
  3. 催促：CS期日の1週間前20時・3日前20時・当日8時（既定）に、未提出の人だけをメンションして催促する。秘匿の送り先がある人にはそこで1人ずつ。期限を過ぎたら GM に未提出の人を知らせる。
    • 各段階は1回だけ。連携が遅れて複数の段階を過ぎていたら、いちばん新しい段階だけ送る。
    • 期日に時刻があればその時刻が期限、日付だけならその日の終わり。朝より早い期限でも、当日分は期限の2時間前までに送る。
    • CS期日を変えると、新しい期日で数え直す。

4.2 準備タスクの自動完了

CS が全員分そろい（CS 提出が無い卓は見ない）、セッションルームの URL が登録され、状況が「セッション開始待ち」か「セッション中」の卓について、やることリストの未完了タスクのうちシナリオ名の合うものが1件だけなら「完了」にして GM に知らせる。複数あれば完了にせず候補を知らせる。卓ごとに1回だけ。

4.3 セッションの通知（日程は「セッション日程」DB）

  • 「中止」の回は無かったものとして扱う（通知しない。初回の判定からも外す）。
  • 「通知しない」の回は日程として残すが、前日のお知らせを送らない。初回が「通知しない」なら開始前のお知らせも送らない。
  • 「セッション日程」に行が1件も無い卓は、卓予定の「セッション日時」を1回分として使う。
  • 「日時」は開始〜終了。Bot が回を作るとき（取り込み・追加・リスケ）の終了は、18時以降開始ならその日の24時、それより前なら18時（既定）。手で直した終了はそのまま使う。
  • 前日のお知らせ：各回の前日20時から開始までの間に1回、参加者全員をメンションして送る（日付だけの回はその日いっぱいまで）。その時点でセッションルームの URL が登録済みなら一緒に付け、「送った」と記録する（2日目以降の回にも付ける）。URL が未登録でまだ送っていなければ、GM に知らせる。
  • 開始前のお知らせ：初回の開始30分前から開始2時間後までの間に1回だけ、メンションなしで送る。セッションルームの URL をまだ送っていなければ URL を付け、送ってあるか未登録なら URL なしで送る。初回に時刻が無い卓には送らない。2日目以降は送らない。
  • セッション中：初回の開始時刻を過ぎたら、状況が「セッション開始待ち」の卓を「セッション中」にする。
  • リスケ（日時の書き換え）をしたら、新しい日時で送り直す（送った記録は回の日時ごと）。
  • 予定より早く終わったら /卓 終了 で残りの通知をすべて止める。

4.4 夜間（23時〜8時、既定）

  • 参加者向けの通知（CS の催促・前日のお知らせ・開始前のお知らせ）は送らない。催促と前日のお知らせは8時以降に送る。開始前のお知らせは、夜間に送る時刻が来る卓（深夜・早朝に始まる卓）では送られない。
  • GM あての通知（全員提出・期限超過・準備タスク）は夜間も送る。URL 未登録の知らせは前日のお知らせと一緒に出すので、朝まで待つ。

5. 毎朝の確認（9時）

照合結果（5.1・5.2）は、既定の管理先（無ければ GM の DM）に1通にまとめて送る。何も無ければ送らない。

5.1 カレンダーとの照合（カレンダーを使うときだけ）

完了・流卓以外の卓予定（PL の卓も含む）と、カレンダーの今日から180日先までの予定を比べ、次を知らせる。

  • 予定があるのに、状況が日程決定前のまま
  • 状況が「CS待ち」「セッション開始待ち」「セッション中」なのに、今後の予定が無い
  • カレンダーの予定に当たる卓予定が無い（同じシナリオはいちばん近い日付で1件）
  • 次の予定の説明欄の GM・PL が卓予定と違う（説明欄の GM： PL：。PL に「未定」「募集」があれば PL は比べない）
  • カレンダーに繰り返し予定がある（2回目以降は読めない）

予定と卓の結び付け方：予定名とシナリオ名（＋「カレンダー表記」に | 区切りで書いた別名）を、全角／半角・大文字／小文字・空白・記号を無視して比べる。完全一致、名前を含む（3文字以上）、または副題を省いた書き方（6文字以上で、短い方の文字が同じ順番で長い方に含まれる）を同じ卓とみなす。

5.2 流卓予定日の知らせ

卓予定の「流卓予定日」が入っていて、流卓・完了になっていない卓（PL の卓も含む）について、次の3回だけ照合結果に載せる。カレンダーを使っていなくても載せる。

  • 流卓予定日の14日前（既定）
  • 流卓予定日の当日（過ぎた日）。仮立卓は 5.3 のボタン付きの知らせを送るので、照合結果には載せない
  • 過ぎて30日（既定）たってもそのまま

送った段階は流卓予定日ごとに記録する（日付を変えたら知らせ直す）。すでに先の段階にある卓は、今の段階だけを1回載せる。/卓 照合 では記録せず、今の段階をそのまま出す。

5.3 仮立卓のリマインド

  • 仮立卓：告知先（チャンネル）がつながっていて、状況が日程決定前の卓。4. の通知は送らない。
  • 流卓予定日が空なら、チャンネルの作成日（チャンネル ID から読む）の365日後（既定）を書き込む（/卓 チャンネル のときと、毎朝の確認で。入っている日付は変えない）。照合より先に行う。
  • 流卓予定日の日になったら、GM 向けの送り先に、［PL に知らせる］［続ける（もう1年待つ）］のボタン付きで知らせる。流卓予定日ごとに1回だけ。
  • PL には自動では知らせない。 GM が［PL に知らせる］を押したときだけ、卓のチャンネルで、PL 欄の名前から探したメンバーをメンションして知らせる（見つからない人には付けない）。1回だけ。押したあとも［続ける］は残す。
  • ［続ける］を押すと、流卓予定日を今日の365日後（既定）に書き換え、また最初から知らせる。

制約

  • 無料プランの外部リクエスト上限（1回50件）のため、1回の確認で読むチャンネルは20件まで。足りなければ次の回に回す。
  • 各チャンネルは直近50件のメッセージだけを見る。
  • テキストで貼られた CS は検出しない。
  • カレンダーの繰り返し予定は、2回目以降を読めない（照合で知らせる）。
  • 秘匿の送り先に DM は使えない。
  • プライベートチャンネル・非公開スレッドは、Bot をメンバーに追加しないと読み書きできない。
  • 「卓」欄の候補が出ないとき・コマンドを登録し直したあとは、Discord を完全に終了して開き直す。
